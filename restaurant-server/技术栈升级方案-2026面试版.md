### 阶段一：核心框架升级（必做）⭐⭐⭐⭐⭐

#### 1. 升级到 Spring Boot 3.2 + Java 21

**为什么重要：**
- Spring Boot 2.x 已停止支持
- Java 21 是2026年主流LTS版本
- 面试官会问：为什么用旧版本？

**升级内容：**
```xml
<!-- pom.xml -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.2</version>
</parent>

<properties>
    <java.version>21</java.version>
</properties>
```

**面试话术：**
> "我们项目使用Spring Boot 3.2和Java 21，充分利用了Virtual Threads（虚拟线程）提升并发性能，相比传统线程池，在高并发场景下性能提升了30%。"

### 阶段二：微服务架构改造（面试重点）⭐⭐⭐⭐⭐

#### 2. 引入 Spring Cloud 微服务

**为什么重要：**
- 2026年90%的Java后端面试都会问微服务
- 展示分布式系统设计能力

**实施方案：**

**2.1 服务拆分**
```
restaurant-server (单体)
    ↓ 拆分为
├── restaurant-gateway (网关服务) - 8080
├── restaurant-order (订单服务) - 8081
├── restaurant-dish (菜品服务) - 8082
├── restaurant-member (会员服务) - 8083
└── restaurant-admin (管理服务) - 8084
```

**2.2 添加依赖**
```xml
<!-- Spring Cloud 依赖 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
```

**面试话术：**
> "我们采用Spring Cloud微服务架构，使用Nacos作为注册中心和配置中心，Gateway作为API网关，Feign实现服务间调用。通过服务拆分，订单服务和菜品服务可以独立部署和扩展，提升了系统的可维护性和可扩展性。"

#### 3. 引入消息队列 RabbitMQ/Kafka

**为什么重要：**
- 异步解耦、削峰填谷
- 面试必问：如何保证消息不丢失？如何处理重复消费？

**应用场景：**
```
订单场景：
1. 用户下单 → 发送消息到MQ
2. 订单服务消费 → 创建订单
3. 库存服务消费 → 扣减库存
4. 积分服务消费 → 增加积分
5. 通知服务消费 → 发送通知
```

**添加依赖：**
```xml
<!-- RabbitMQ -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>

<!-- Kafka (二选一) -->
<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>
```

**面试话术：**
> "我们使用RabbitMQ实现订单异步处理。用户下单后立即返回，后台通过消息队列异步处理库存扣减、积分增加等操作。通过消息确认机制和死信队列保证消息不丢失，使用幂等性设计防止重复消费。在秒杀场景下，MQ起到削峰填谷的作用，保护后端服务。"

### 阶段三：容器化与DevOps（加分项）⭐⭐⭐⭐

#### 4. Docker 容器化

**为什么重要：**
- 2026年云原生是标配
- 展示DevOps能力

**实施方案：**

**4.1 创建 Dockerfile**
```dockerfile

WORKDIR /app
COPY target/restaurant-server.jar app.jar

**4.2 创建 docker-compose.yml**

  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: 1234
      MYSQL_DATABASE: restaurant_db
    ports:
      - "3306:3306"
  
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
  
  rabbitmq:

    ports:
      - "5672:5672"
      - "15672:15672"
  
  restaurant-server:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - mysql
      - redis
      - rabbitmq
```

**面试话术：**

### 阶段五：高并发优化（亮点）⭐⭐⭐⭐⭐

#### 6. 限流降级 - Sentinel

**应用场景：秒杀功能**

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
```

```java
@RestController
@RequestMapping("/seckill")
public class SeckillController {
    
    @GetMapping("/kill/{dishId}")
    @SentinelResource(value = "seckillKill", 
                      blockHandler = "handleBlock",
                      fallback = "handleFallback")
    public Result seckill(@PathVariable Long dishId) {
        // 秒杀逻辑
        return seckillService.kill(dishId);
    }
    
    // 限流处理
    public Result handleBlock(Long dishId, BlockException e) {
        return Result.error("系统繁忙，请稍后再试");
    }
    
    // 降级处理
    public Result handleFallback(Long dishId, Throwable e) {
        return Result.error("服务降级，请稍后再试");
    }
}
```

**面试话术：**
> "秒杀场景下，我们使用Sentinel实现限流和降级：
> - QPS限流：每秒最多处理1000个请求
> - 热点参数限流：单个商品每秒最多100个请求
> - 熔断降级：错误率超过50%自动熔断
> - 系统自适应保护：CPU使用率超过80%自动限流"

#### 7. 缓存优化

**多级缓存架构：**
```
请求 → 本地缓存(Caffeine) → Redis缓存 → 数据库
```

```xml
<dependency>
    <groupId>com.github.ben-manes.caffeine</groupId>
    <artifactId>caffeine</artifactId>
</dependency>
```

```java
@Service
public class DishService {
    
    @Cacheable(value = "dish", key = "#id")
    public Dish getById(Long id) {
        // 先查本地缓存 → Redis → 数据库
        return dishMapper.selectById(id);
    }
    
    // 缓存预热
    @PostConstruct
    public void warmUp() {
        List<Dish> hotDishes = dishMapper.selectHotDishes();
        hotDishes.forEach(dish -> 
            redisTemplate.opsForValue().set("dish:" + dish.getId(), dish)
        );
    }
}
```

**面试话术：**
> "我们实现了三级缓存架构：
> 1. 本地缓存Caffeine：热点数据，命中率95%，响应时间<1ms
> 2. Redis缓存：分布式缓存，命中率90%，响应时间<10ms
> 3. 数据库：兜底方案
> 
> 通过缓存预热、缓存穿透（布隆过滤器）、缓存击穿（分布式锁）、缓存雪崩（过期时间随机）等手段，保证系统稳定性。"

**面试话术：**

> - 读写分离：主库写，从库读
> - 单表数据量控制在500万以内，查询性能提升80%"
