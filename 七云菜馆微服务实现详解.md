### 2.3 使用Feign客户端

```java
@Service
public class OrderService {
    
    @Autowired
    private DishServiceClient dishServiceClient;
    
    public OrderDTO createOrder(OrderRequest request) {
        // 1. 查询菜品信息
        Result<DishDTO> dishResult = dishServiceClient
            .getDishById(request.getDishId());
        
        if (!dishResult.isSuccess()) {
            throw new BusinessException("菜品信息获取失败");
        }
        
        DishDTO dish = dishResult.getData();
        
        // 2. 创建订单
        Order order = new Order();
        order.setUserId(request.getUserId());
        order.setDishId(dish.getId());
        order.setDishName(dish.getName());
        order.setPrice(dish.getPrice());
        order.setQuantity(request.getQuantity());
        order.setTotalAmount(dish.getPrice() * request.getQuantity());
        orderMapper.insert(order);
        
        // 3. 扣减库存（异步处理）
        dishServiceClient.decreaseStock(
            dish.getId(), 
            request.getQuantity()
        );
        
        return convertToDTO(order);
    }
}
```

### 3.2 统一认证过滤器

```java
@Component
@Slf4j
public class AuthFilter implements GlobalFilter, Ordered {
    
    @Autowired
    private JwtUtil jwtUtil;
    
    // 白名单：不需要认证的路径
    private static final List<String> WHITE_LIST = Arrays.asList(
        "/api/members/login",
        "/api/members/register",
        "/api/dishes/list"
    );
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, 
                             GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        String path = request.getPath().value();
        
        // 白名单放行
        if (isWhiteList(path)) {
            return chain.filter(exchange);
        }
        
        // 获取Token
        String token = request.getHeaders().getFirst("Authorization");
        
        if (StringUtils.isEmpty(token)) {
            return unauthorized(exchange, "未登录");
        }
        
        // 验证Token
        try {
            Claims claims = jwtUtil.parseToken(token);
            Long userId = claims.get("userId", Long.class);
            
            // 将用户信息传递给下游服务
            ServerHttpRequest newRequest = request.mutate()
                .header("X-User-Id", userId.toString())
                .build();
            
            return chain.filter(
                exchange.mutate().request(newRequest).build()
            );
            
        } catch (Exception e) {
            log.error("Token验证失败", e);
            return unauthorized(exchange, "Token无效");
        }
    }
    
    private boolean isWhiteList(String path) {
        return WHITE_LIST.stream()
            .anyMatch(path::startsWith);
    }
    
    private Mono<Void> unauthorized(ServerWebExchange exchange, 
                                    String message) {
        ServerHttpResponse response = exchange.getResponse();
        response.setStatusCode(HttpStatus.UNAUTHORIZED);
        response.getHeaders().setContentType(MediaType.APPLICATION_JSON);
        
        String body = String.format(
            "{\"code\":401,\"message\":\"%s\"}", 
            message
        );
        
        DataBuffer buffer = response.bufferFactory()
            .wrap(body.getBytes(StandardCharsets.UTF_8));
        
        return response.writeWith(Mono.just(buffer));
    }
    
    @Override
    public int getOrder() {
        return -100;  // 优先级最高
    }
}
```

### 3.4 全局异常处理

```java
@Component
@Slf4j
public class GlobalExceptionHandler implements ErrorWebExceptionHandler {
    
    @Override
    public Mono<Void> handle(ServerWebExchange exchange, 
                            Throwable ex) {
        ServerHttpResponse response = exchange.getResponse();
        
        if (response.isCommitted()) {
            return Mono.error(ex);
        }
        
        response.getHeaders()
            .setContentType(MediaType.APPLICATION_JSON);
        
        String message;
        HttpStatus status;
        
        if (ex instanceof ResponseStatusException) {
            ResponseStatusException rse = (ResponseStatusException) ex;
            status = (HttpStatus) rse.getStatusCode();
            message = rse.getReason();
        } else {
            status = HttpStatus.INTERNAL_SERVER_ERROR;
            message = "系统异常";
            log.error("网关异常", ex);
        }
        
        response.setStatusCode(status);
        
        String body = String.format(
            "{\"code\":%d,\"message\":\"%s\"}", 
            status.value(), 
            message
        );
        
        DataBuffer buffer = response.bufferFactory()
            .wrap(body.getBytes(StandardCharsets.UTF_8));
        
        return response.writeWith(Mono.just(buffer));
    }
}
```

## 4️⃣ 限流熔断 (Sentinel)

### 4.1 限流配置

**Controller层限流**：
```java
@RestController
@RequestMapping("/orders")
public class OrderController {
    
    @PostMapping
    @SentinelResource(
        value = "createOrder",  // 资源名
        blockHandler = "createOrderBlockHandler",  // 限流处理
        fallback = "createOrderFallback"  // 异常降级
    )
    public Result<OrderDTO> createOrder(@RequestBody OrderRequest request) {
        return Result.success(orderService.createOrder(request));
    }
    
    // 限流处理方法
    public Result<OrderDTO> createOrderBlockHandler(
            OrderRequest request, 
            BlockException ex) {
        log.warn("创建订单被限流，userId={}", request.getUserId());
        return Result.error("系统繁忙，请稍后再试");
    }
    
    // 异常降级方法
    public Result<OrderDTO> createOrderFallback(
            OrderRequest request, 
            Throwable ex) {
        log.error("创建订单异常", ex);
        return Result.error("订单创建失败，请重试");
    }
}
```

**Nacos配置** - `restaurant-order-flow-rules`：
```json
[
  {
    "resource": "createOrder",
    "grade": 1,
    "count": 100,
    "strategy": 0,
    "controlBehavior": 0
  }
]
```

**规则说明**：
- `resource`: 资源名
- `grade`: 限流阈值类型（1=QPS）
- `count`: 阈值（100 QPS）
- `strategy`: 流控模式（0=直接）
- `controlBehavior`: 流控效果（0=快速失败）

**熔断流程**：
```

2. 统计异常比例
3. 异常比例 > 50% 且请求数 >= 5
4. 触发熔断（10秒内直接降级）
5. 10秒后进入半开状态
6. 尝试恢复调用
```

```java
@Configuration
public class RabbitMQConfig {
```

### 5.2 生产者发送消息

```java
@Service
@Slf4j
public class OrderService {
    
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    public OrderDTO createOrder(OrderRequest request) {
        // 1. 创建订单
        Order order = new Order();
        order.setUserId(request.getUserId());
        order.setDishId(request.getDishId());
        order.setQuantity(request.getQuantity());
        order.setTotalAmount(request.getTotalAmount());
        order.setStatus("PENDING");
        orderMapper.insert(order);
        
        // 2. 发送消息到MQ（异步处理）
        OrderMessage message = OrderMessage.builder()
            .orderId(order.getId())
            .userId(order.getUserId())
            .dishId(order.getDishId())
            .quantity(order.getQuantity())
            .createTime(new Date())
            .build();
        
        rabbitTemplate.convertAndSend(
            "order.exchange",
            "order.create",
            message,
            msg -> {
                // 设置消息属性
                msg.getMessageProperties().setDeliveryMode(
                    MessageDeliveryMode.PERSISTENT  // 持久化
                );
                msg.getMessageProperties().setExpiration("1800000");  // 30分钟过期
                return msg;
            }
        );
        
        log.info("订单创建成功，orderId={}", order.getId());
        
        // 3. 立即返回（不等待后续处理）
        return convertToDTO(order);
    }
}
```

### 5.3 消费者处理消息

```java
@Component
@Slf4j
public class OrderMessageConsumer {
    
    @Autowired
    private DishServiceClient dishServiceClient;
    
    @Autowired
    private OrderService orderService;
    
    @RabbitListener(queues = "order.queue")
    public void handleOrderCreate(OrderMessage message) {
        log.info("收到订单创建消息，orderId={}", message.getOrderId());
        
        try {
            // 1. 扣减库存
            Result<Void> stockResult = dishServiceClient.decreaseStock(
                message.getDishId(), 
                message.getQuantity()
            );
            
            if (!stockResult.isSuccess()) {
                throw new BusinessException("库存扣减失败");
            }
            
            // 2. 更新订单状态
            orderService.updateStatus(
                message.getOrderId(), 
                "PROCESSING"
            );
            
            // 3. 发送通知（可选）
            // notificationService.sendOrderNotification(message);
            
            log.info("订单处理完成，orderId={}", message.getOrderId());
            
        } catch (Exception e) {
            log.error("订单处理失败，orderId={}", message.getOrderId(), e);
            // 抛出异常，消息会重新入队或进入死信队列
            throw e;
        }
    }
    
    // 死信队列消费者（处理失败的消息）
    @RabbitListener(queues = "order.dlx.queue")
    public void handleOrderDlx(OrderMessage message) {
        log.error("订单处理失败进入死信队列，orderId={}", message.getOrderId());
        
        // 记录到数据库，等待人工处理
        orderService.updateStatus(message.getOrderId(), "FAILED");
        
        // 发送告警通知
        // alertService.sendAlert("订单处理失败", message);
    }
}
```

**处理超时订单**：
```java
@Component
@Slf4j
public class OrderTimeoutConsumer {
    
    @Autowired
    private OrderService orderService;
    
    @Autowired
    private DishServiceClient dishServiceClient;
    
    @RabbitListener(queues = "order.cancel.queue")
    public void handleOrderTimeout(Long orderId) {
        log.info("处理超时订单，orderId={}", orderId);
        
        Order order = orderService.getById(orderId);
        
        // 如果订单还是未支付状态，自动取消
        if ("PENDING".equals(order.getStatus())) {
            // 1. 更新订单状态
            order.setStatus("CANCELLED");
            order.setCancelReason("超时未支付");
            orderService.updateById(order);
            
            // 2. 恢复库存
            dishServiceClient.increaseStock(
                order.getDishId(), 
                order.getQuantity()
            );
            
            log.info("订单已自动取消，orderId={}", orderId);
        }
    }
}
```

**流程说明**：
```
1. 创建订单 → 发送延迟消息到 order.delay.queue
2. 30分钟后消息过期 → 进入死信队列 order.cancel.queue
3. 消费者处理 → 检查订单状态
4. 如果未支付 → 取消订单 + 恢复库存
5. 如果已支付 → 忽略消息
```

## 6️⃣ 多级缓存架构

### 6.1 三级缓存设计

```
L1: Caffeine (本地缓存)
    - 容量: 10000条
    - 过期: 5分钟
    - 命中率: 95%
    - 响应: <1ms

L2: Redis (分布式缓存)
    - 过期: 5-10分钟（随机）
    - 命中率: 90%
    - 响应: <10ms

L3: MySQL (数据库)
    - 响应: <100ms
```

### 6.2 Caffeine本地缓存

**配置类**：
```java
@Configuration
public class CaffeineConfig {
    
    @Bean
    public Cache<String, Object> caffeineCache() {
        return Caffeine.newBuilder()
            .maximumSize(10000)  // 最大容量
            .expireAfterWrite(5, TimeUnit.MINUTES)  // 写入后5分钟过期
            .recordStats()  // 记录统计信息
            .build();
    }
}
```

**使用示例**：
```java
@Service
public class DishService {
    
    @Autowired
    private Cache<String, Object> caffeineCache;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private DishMapper dishMapper;
    
    public DishDTO getDishById(Long id) {
        String cacheKey = "dish:" + id;
        
        // L1: Caffeine缓存
        DishDTO dish = (DishDTO) caffeineCache.getIfPresent(cacheKey);
        if (dish != null) {
            log.debug("Caffeine缓存命中，dishId={}", id);
            return dish;
        }
        
        // L2: Redis缓存
        dish = (DishDTO) redisTemplate.opsForValue().get(cacheKey);
        if (dish != null) {
            log.debug("Redis缓存命中，dishId={}", id);
            // 回写到Caffeine
            caffeineCache.put(cacheKey, dish);
            return dish;
        }
        
        // L3: 数据库查询
        Dish entity = dishMapper.selectById(id);
        if (entity == null) {
            return null;
        }
        
        dish = convertToDTO(entity);
        
        // 写入缓存
        redisTemplate.opsForValue().set(
            cacheKey, 
            dish, 
            5 + new Random().nextInt(5),  // 5-10分钟随机过期
            TimeUnit.MINUTES
        );
        caffeineCache.put(cacheKey, dish);
        
        log.debug("数据库查询，dishId={}", id);
        return dish;
    }
}
```

#### 6.3.2 防缓存击穿（分布式锁）

```java
@Service
public class DishService {
    
    @Autowired
    private RedissonClient redissonClient;
    
    public DishDTO getDishById(Long id) {
        String cacheKey = "dish:" + id;
        
        // 查询缓存
        DishDTO dish = getFromCache(cacheKey);
        if (dish != null) {
            return dish;
        }
        
        // 缓存未命中，使用分布式锁
        String lockKey = "lock:dish:" + id;
        RLock lock = redissonClient.getLock(lockKey);
        
        try {
            // 尝试获取锁（等待10秒，锁30秒后自动释放）
            if (lock.tryLock(10, 30, TimeUnit.SECONDS)) {
                try {
                    // 双重检查：再次查询缓存
                    dish = getFromCache(cacheKey);
                    if (dish != null) {
                        return dish;
                    }
                    
                    // 查询数据库
                    Dish entity = dishMapper.selectById(id);
                    if (entity == null) {
                        // 缓存空值，防止缓存穿透
                        redisTemplate.opsForValue().set(
                            cacheKey, 
                            new DishDTO(),  // 空对象
                            2, 
                            TimeUnit.MINUTES
                        );
                        return null;
                    }
                    
                    dish = convertToDTO(entity);
                    
                    // 写入缓存
                    redisTemplate.opsForValue().set(
                        cacheKey, 
                        dish, 
                        5 + new Random().nextInt(5), 
                        TimeUnit.MINUTES
                    );
                    
                    return dish;
                    
                } finally {
                    lock.unlock();
                }
            } else {
                // 获取锁失败，等待后重试
                Thread.sleep(100);
                return getDishById(id);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("获取菜品信息失败");
        }
    }
}
```

### 7.2 分库分表

**ShardingSphere分片配置**：
```yaml
spring:
  shardingsphere:
    rules:
      sharding:
        tables:
          # 订单表分片
          t_order:
            actual-data-nodes: ds_$->{0..15}.t_order_$->{2026_01..2026_12}
            
            # 数据库分片策略（按user_id哈希）
            database-strategy:
              standard:
                sharding-column: user_id
                sharding-algorithm-name: order-database-inline
            
            # 表分片策略（按create_time时间）
            table-strategy:
              standard:
                sharding-column: create_time
                sharding-algorithm-name: order-table-inline
            
            # 主键生成策略
            key-generate-strategy:
              column: id
              key-generator-name: snowflake
        
        sharding-algorithms:
          # 数据库分片算法
          order-database-inline:
            type: INLINE
            props:
              algorithm-expression: ds_$->{user_id % 16}
          
          # 表分片算法
          order-table-inline:
            type: INLINE
            props:
              algorithm-expression: t_order_$->{create_time.format('yyyy_MM')}
        
        key-generators:
          snowflake:
            type: SNOWFLAKE
            props:
              worker-id: 1
```

**分片规则说明**：
```
数据库分片：
- 按user_id哈希取模
- 16个数据库：ds_0 ~ ds_15
- 示例：user_id=12345 → 12345 % 16 = 9 → ds_9

表分片：
- 按create_time时间分表
- 按月分表：t_order_2026_01, t_order_2026_02, ...
- 示例：create_time=2026-02-15 → t_order_2026_02

最终路由：
user_id=12345, create_time=2026-02-15
→ ds_9.t_order_2026_02
```

## 🔟 面试要点总结

### 微服务架构优势
- **服务独立部署**：单个服务故障不影响其他服务
- **技术栈灵活**：不同服务可使用不同技术
- **弹性伸缩**：根据负载动态扩缩容
- **团队协作**：不同团队负责不同服务

### 核心组件选型理由

**Nacos vs Eureka**：
- Nacos支持AP和CP模式，Eureka只支持AP
- Nacos集成配置中心，Eureka需要Config Server
- Nacos性能更好，社区更活跃

**Sentinel vs Hystrix**：
- Sentinel轻量级，性能更好
- Sentinel支持实时监控和规则动态配置
- Hystrix已停止维护

**Gateway vs Zuul**：
- Gateway基于WebFlux，性能更好
- Gateway是Spring官方推荐
- Zuul 2.x发布较晚，生态不如Gateway

**RabbitMQ vs Kafka**：
- RabbitMQ功能丰富（延迟队列、死信队列）
- RabbitMQ易于使用和运维
- Kafka适合大数据场景，本项目选RabbitMQ

### 常见问题解答

**Q: 如何保证分布式事务一致性？**
A: 使用RabbitMQ实现最终一致性，关键场景可使用Seata强一致性。

**Q: 如何防止缓存穿透、击穿、雪崩？**
A: 
- 穿透：布隆过滤器 + 缓存空值
- 击穿：分布式锁
- 雪崩：过期时间随机化 + 缓存预热

**Q: 如何实现服务限流？**
A: 使用Sentinel，支持QPS限流、热点参数限流、系统自适应保护。

**Q: 如何监控微服务？**
A: Prometheus采集指标 + Grafana可视化 + SkyWalking链路追踪。
