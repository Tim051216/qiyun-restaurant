3. **功能完善**：服务注册、配置中心、限流熔断一站式解决
4. **文档友好**：中文文档完善，学习成本低
5. **阿里背景**：经过阿里双 11 验证，稳定可靠"

---

### 5.2 高并发问题

**Q: 如何保证秒杀场景下不超卖？**

"我们使用 Redis + Lua 脚本实现原子性库存扣减：

1. **原子性保证**：Lua 脚本在 Redis 中以原子方式执行，不会被打断
2. **先检查后扣减**：先检查库存是否充足，再扣减，整个过程原子化
3. **高性能**：Redis 内存操作，QPS 可达 10 万+
4. **防超卖**：即使高并发场景，也能保证库存不会为负

具体实现：
```lua
-- 检查库存
local stock = redis.call('get', KEYS[1])
if tonumber(stock) < tonumber(ARGV[1]) then
    return 0  -- 库存不足
end
-- 扣减库存
redis.call('decrby', KEYS[1], ARGV[1])
return 1  -- 扣减成功
```

这个方案让我们的 QPS 从 500 提升到 10,000，超卖率从 5% 降到 0%。"

---

### 5.3 消息队列问题

**Q: 如何保证 RabbitMQ 消息不丢失、不重复？**

"我们从三个方面保证消息可靠性：

**1. 消息不丢失**：
- 生产者确认：使用 publisher confirms 机制
- 消息持久化：队列和消息都设置为持久化
- 消费者确认：手动 ACK，处理成功后才确认

**2. 消息不重复**：
- 幂等性检查：使用 Redis SETNX 记录已消费的消息 ID
- 业务幂等：订单创建时检查订单是否已存在

**3. 消息不丢失（异常处理）**：
- 重试机制：失败自动重试 3 次
- 死信队列：超过重试次数进入死信队列
- 人工介入：死信队列消息可以人工处理"

---

### 5.4 监控问题

**Q: 如何快速定位微服务性能问题？**

"我们使用 SkyWalking 进行分布式链路追踪：

1. **链路追踪**：看到请求在各个服务间的调用关系和耗时
2. **TraceId 关联**：通过 TraceId 关联日志，快速定位问题
3. **性能监控**：实时监控服务的 QPS、响应时间、错误率
4. **服务拓扑**：自动生成服务依赖关系图

**实际案例**：
- 发现订单创建慢（2 秒）
- 通过链路追踪定位到库存扣减接口慢
- 优化方案：改用 Redis + Lua 脚本
- 效果：响应时间从 2 秒降到 50ms"

---

### 5.5 技术深度问题

**Q: 说说 SkyWalking 的工作原理？**

"SkyWalking 使用 Java Agent 字节码增强技术：

1. **Agent 启动**：应用启动时加载 SkyWalking Agent（-javaagent 参数）
2. **字节码增强**：Agent 拦截关键类（HTTP 客户端、数据库驱动），插入追踪代码
3. **数据收集**：拦截到的调用信息（TraceId、SpanId、耗时）发送到 OAP Server
4. **数据存储**：OAP Server 将数据存储到 Elasticsearch
5. **数据展示**：SkyWalking UI 从 OAP Server 查询数据并展示

**优点**：
- 无侵入：不需要修改业务代码
- 性能影响小：异步上报，对业务影响很小
- 功能强大：自动追踪 HTTP、RPC、数据库、消息队列"
