# 监控系统使用指南

## 概述

项目已集成完整的监控系统，包括 **Prometheus** 和 **Grafana**，用于实时监控微服务的运行状态和性能指标。

## 监控架构

```
微服务应用 (暴露指标)
    ↓
Prometheus (收集和存储指标)
    ↓
Grafana (可视化展示)
```

---

## 1. Prometheus - 指标收集

### 什么是 Prometheus？

Prometheus 是一个开源的监控和告警系统，专门用于收集和存储时间序列数据。

### 功能特点

- ✅ **指标收集**：自动从应用程序抓取性能指标
- ✅ **时序数据库**：高效存储时间序列数据
- ✅ **强大查询**：提供 PromQL 查询语言
- ✅ **告警支持**：可配置告警规则

### 访问信息

- **地址**：http://localhost:9090
- **状态**：✅ 已运行（通过 Docker 容器）
- **容器名**：restaurant-prometheus

### 使用方法

#### 1. 访问 Prometheus UI

打开浏览器访问：http://localhost:9090

#### 2. 查询指标

在查询框中输入 PromQL 表达式，例如：

**查看 JVM 内存使用**：
```promql
jvm_memory_used_bytes{application="gateway"}
```

**查看 HTTP 请求数**：
```promql
http_server_requests_seconds_count
```

**查看 CPU 使用率**：
```promql
process_cpu_usage
```

#### 3. 查看目标状态

点击 "Status" → "Targets" 查看所有监控目标的状态。

应该看到：
- ✅ gateway (8080)
- ✅ dish-service (8082)
- ✅ order-service (8081)
- ✅ member-service (8083)
- ✅ admin-service (8084)

### 配置文件

配置文件位置：`restaurant-server/monitoring/prometheus.yml`

```yaml
global:
  scrape_interval: 15s  # 每15秒抓取一次指标

scrape_configs:
  - job_name: 'spring-boot-apps'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets:
        - 'host.docker.internal:8080'  # Gateway
        - 'host.docker.internal:8081'  # Order Service
        - 'host.docker.internal:8082'  # Dish Service
        - 'host.docker.internal:8083'  # Member Service
        - 'host.docker.internal:8084'  # Admin Service
```

### 什么是 Grafana？

Grafana 是一个开源的数据可视化和监控平台，可以将 Prometheus 收集的数据以图表形式展示。

### 功能特点

- ✅ **漂亮的仪表盘**：创建专业的监控仪表盘
- ✅ **多种图表**：折线图、柱状图、饼图、热力图等
- ✅ **告警通知**：支持邮件、Slack、钉钉等通知方式
- ✅ **多数据源**：支持 Prometheus、MySQL、InfluxDB 等

## 3. 监控指标说明

### JVM 指标

| 指标名称 | 说明 |
|---------|------|
| `jvm_memory_used_bytes` | JVM 内存使用量 |
| `jvm_memory_max_bytes` | JVM 最大内存 |
| `jvm_gc_pause_seconds` | GC 暂停时间 |
| `jvm_threads_live` | 活跃线程数 |
| `jvm_classes_loaded` | 已加载类数量 |

### HTTP 指标

| 指标名称 | 说明 |
|---------|------|
| `http_server_requests_seconds_count` | HTTP 请求总数 |
| `http_server_requests_seconds_sum` | HTTP 请求总耗时 |
| `http_server_requests_seconds_max` | HTTP 请求最大耗时 |

### 数据库指标

| 指标名称 | 说明 |
|---------|------|
| `hikaricp_connections_active` | 活跃数据库连接数 |
| `hikaricp_connections_idle` | 空闲数据库连接数 |
| `hikaricp_connections_pending` | 等待中的连接请求 |

### 缓存指标

| 指标名称 | 说明 |
|---------|------|
| `cache_gets_total` | 缓存查询总数 |
| `cache_hits_total` | 缓存命中数 |
| `cache_misses_total` | 缓存未命中数 |

### 业务指标

| 指标名称 | 说明 |
|---------|------|
| `order_created_total` | 订单创建总数 |
| `dish_query_total` | 菜品查询总数 |
| `member_register_total` | 会员注册总数 |

## 4. 常用监控场景

### 场景1：监控服务健康状态

**Prometheus 查询**：
```promql
up{job="spring-boot-apps"}
```
- 返回 1 表示服务正常
- 返回 0 表示服务异常

### 场景2：监控 API 响应时间

**Prometheus 查询**：
```promql
rate(http_server_requests_seconds_sum[5m]) / rate(http_server_requests_seconds_count[5m])
```
- 计算最近 5 分钟的平均响应时间

### 场景3：监控内存使用率

**Prometheus 查询**：
```promql
jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"} * 100
```
- 计算堆内存使用百分比

### 场景4：监控 GC 频率

**Prometheus 查询**：
```promql
rate(jvm_gc_pause_seconds_count[5m])
```
- 计算最近 5 分钟的 GC 次数

### 场景5：监控缓存命中率

**Prometheus 查询**：
```promql
cache_hits_total / (cache_hits_total + cache_misses_total) * 100
```
- 计算缓存命中率百分比

## 5. 告警配置

### 在 Grafana 中配置告警

#### 1. 创建告警规则

1. 打开仪表盘
2. 点击面板标题 → "Edit"
3. 切换到 "Alert" 标签
4. 点击 "Create Alert"
5. 配置告警条件：
   - **When**: 选择指标和阈值
   - **For**: 持续时间
   - **Conditions**: 告警条件

#### 2. 配置通知渠道

1. 点击左侧菜单 "🔔 Alerting" → "Notification channels"
2. 点击 "Add channel"
3. 选择通知方式：
   - Email
   - Slack
   - 钉钉
   - 企业微信
4. 配置通知参数
5. 点击 "Test" 测试
6. 点击 "Save"

### 常用告警规则示例

#### 告警1：内存使用率超过 80%

```yaml
alert: HighMemoryUsage
expr: jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"} > 0.8
for: 5m
annotations:
  summary: "内存使用率过高"
  description: "{{ $labels.application }} 内存使用率超过 80%"
```

#### 告警2：API 响应时间超过 1 秒

```yaml
alert: SlowAPIResponse
expr: rate(http_server_requests_seconds_sum[5m]) / rate(http_server_requests_seconds_count[5m]) > 1
for: 5m
annotations:
  summary: "API 响应缓慢"
  description: "{{ $labels.uri }} 平均响应时间超过 1 秒"
```

#### 告警3：服务不可用

```yaml
alert: ServiceDown
expr: up{job="spring-boot-apps"} == 0
for: 1m
annotations:
  summary: "服务不可用"
  description: "{{ $labels.instance }} 服务已停止"
```

## 6. 故障排查

### 问题1：Prometheus 无法访问

**检查容器状态**：
```bash
docker ps | grep prometheus
```

**查看日志**：
```bash
docker logs restaurant-prometheus
```

**重启容器**：
```bash
docker restart restaurant-prometheus
```

### 问题2：Grafana 无法连接 Prometheus

**检查网络**：
```bash
docker network inspect restaurant-server_restaurant-network
```

**测试连接**：
```bash
docker exec restaurant-grafana ping prometheus
```

```bash
curl http://localhost:8080/actuator/prometheus
```

## 7. 性能优化建议

### Prometheus 优化

1. **调整抓取间隔**：
   ```yaml
   scrape_interval: 30s  # 降低频率减少负载
   ```

2. **设置数据保留时间**：
   ```bash
   --storage.tsdb.retention.time=15d  # 保留 15 天
   ```

3. **限制内存使用**：
   ```bash
   --storage.tsdb.retention.size=10GB  # 最大 10GB
   ```

### Grafana 优化

1. **使用变量**：在仪表盘中使用变量减少重复配置
2. **设置刷新间隔**：避免过于频繁的刷新
3. **使用缓存**：启用查询缓存提升性能
