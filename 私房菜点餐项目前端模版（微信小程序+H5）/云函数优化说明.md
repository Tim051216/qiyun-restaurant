## 🔧 具体优化措施

### 1. 降低内存配置

**文件：** `uniCloud-aliyun/cloudfunctions/ai-chat/package.json`

**修改：**
```json
{
  "cloudfunction-config": {
    "memorySize": 256,  // 从 512 降到 256
    "timeout": 10       // 从 60 降到 10
  }
}
```

**效果：**
- 内存消耗减少 50%
- 超时时间更合理（AI 通常 2-5 秒响应）

---

### 2. 添加请求频率限制

**文件：** `uniCloud-aliyun/cloudfunctions/ai-chat/index.js`

**新增代码：**
```javascript
// 频率限制配置
const requestCache = {};
const RATE_LIMIT = 10; // 每分钟最多 10 次请求

exports.main = async (event, context) => {
  // 获取用户标识
  const userId = context.OPENID || 'anonymous';
  const now = Date.now();
  
  // 检查频率限制
  if (requestCache[userId]) {
    const { count, timestamp } = requestCache[userId];
    if (now - timestamp < 60000) { // 1 分钟内
      if (count >= RATE_LIMIT) {
        return {
          code: 429,
          success: false,
          message: '请求过于频繁，请稍后再试'
        };
      }
      requestCache[userId].count++;
    } else {
      requestCache[userId] = { count: 1, timestamp: now };
    }
  } else {
    requestCache[userId] = { count: 1, timestamp: now };
  }
  
  // 原有代码...
};
```

**效果：**
- 防止恶意或意外的频繁调用
- 保护免费额度不被快速消耗

### 3. 限制历史记录数量

**文件：** `uniCloud-aliyun/cloudfunctions/ai-chat/index.js`

**新增代码：**
```javascript
const MAX_HISTORY = 5; // 最多保留 5 条历史记录

exports.main = async (event, context) => {
  let { message, history = [] } = event;
  
  // 限制历史记录数量
  if (history.length > MAX_HISTORY) {
    history = history.slice(-MAX_HISTORY);
    console.log('历史记录已截断至', MAX_HISTORY, '条');
  }
  
  // 原有代码...
};
```

**效果：**
- 减少数据传输量
- 降低 API 调用成本
- 保持对话上下文的同时控制资源消耗

## 💡 使用建议

### 日常使用

1. **正常对话**
   - 每次对话间隔 1-2 秒
   - 避免连续快速发送消息

2. **测试调试**
   - 使用 HBuilderX 的"本地运行"功能测试
   - 本地运行不消耗云端资源

3. **监控资源**
   - 定期查看 uniCloud 控制台
   - 关注资源使用情况

### 避免超额

1. **不要频繁测试**
   - 测试时使用本地运行
   - 云端测试间隔至少 5 秒

2. **删除不用的云函数**
   - 检查是否有其他云函数在运行
   - 删除或停用不需要的云函数

3. **定期检查**
   - 每周查看一次资源使用情况
   - 及时发现异常消耗

## ❓ 常见问题

### Q1：优化后会影响 AI 回复质量吗？
A：不会。内存和超时时间的调整不影响 AI 模型本身，回复质量完全一样。

### Q2：为什么要限制历史记录？
A：保留 5 条历史记录足够维持对话上下文，同时减少数据传输和 API 成本。

### Q3：每分钟 10 次请求够用吗？
A：对于正常使用完全够用。人工对话很难达到每分钟 10 次的频率。

### Q4：如何知道优化是否生效？
A：重新上传云函数后，在 uniCloud 控制台查看云函数配置，应该显示内存为 256MB。

### Q5：可以进一步降低内存吗？
A：可以降到 128MB，但可能影响响应速度。建议先使用 256MB 观察效果。
